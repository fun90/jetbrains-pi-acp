# IDEA ↔ pi 功能验证

目的：在 IDEA / Air 中人工检查适配器的核心功能：展示、交互和会话恢复。协议层行为由 `PI_ACP_SMOKE=1 npm test` 自动覆盖，这里只验证客户端界面效果。

## 1. 准备与记录

1. 使用 Node.js 22.19.0 或以上版本，先在终端确认 pi 能正常聊天。
2. 按 README 生成并合并 ACP 配置（源码目录运行 `npm run --silent config`）。更新代码后重启 pi Agent 连接或 IDE。
3. 用一个临时项目作为当前项目，测试文件都放在 `acp-check/` 内。先保存编辑器内容。
4. 模型请求可能产生实际费用。只删除专门创建的测试文件与测试会话。

结果统一填写：`通过 / 失败 / 阻塞 / 不适用`。界面没有入口或客户端没有声明相应能力时记“阻塞”，并在备注中写明原因。

## 2. 基础聊天与控制

| 编号 | 操作或可复制提示 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| B01 | 新建聊天，发送：`请用三句话介绍你能在当前项目里做什么，并用 Markdown 列表回答。` | 回答逐步出现，Markdown 可读；没有 RPC JSON 混入回答；结束后可继续输入。 | |
| B02 | 发送：`记住本次验证口令：青竹482。只回复已记住。`；下一轮问：`刚才的口令是什么？` | 同一会话保留上下文，回答包含 `青竹482`。 | |
| B03 | 在模型菜单切换模型，再切换推理级别，然后发简单问题。 | 菜单值更新，新回合使用新模型；切换模型后推理级别选项同步刷新。 | |
| B04 | 发送：`用 bash 执行 sleep 30，然后回复完成。`；看到工具运行后点击停止，再发：`只回复取消后可继续。` | 执行停止，忙状态结束，新回合可用；不会继续输出“完成”。 | |
| B05 | 执行中再发送一条普通消息。 | 提示被拒绝，并显示“该会话已有正在执行的提示”；原任务不受影响。 | |
| B06 | 附加一个已保存的文本文件要求摘要；对支持图片的模型附加图片要求描述。 | 文件内容或引用到达模型；图片在支持的模型上可用。 | |

## 3. 权限模式

先在完全访问模式下创建 `acp-check/权限.txt`，内容为 `原始内容`。每次都检查磁盘实际内容。

| 编号 | 操作 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| P01 | 切换“标准访问”，要求读取该文件，再要求改为 `已批准`，授权框选“允许本次”。 | 读取无需授权；写入前出现授权，批准后才修改；下次写入仍需授权。 | |
| P02 | 标准访问下要求修改，授权框选“拒绝本次”；再发一次，待授权时点击停止。 | 两次都不修改文件；取消后授权框关闭，聊天可继续。 | |
| P03 | 标准访问下选“本会话始终允许 write”，再要求写文件，然后要求用 bash 执行命令。 | 后续 write 不再询问；bash 仍单独询问。另一会话不受影响。 | |
| P04 | 切换“只读”，要求读取文件，再要求写文件或用 bash 修改文件。 | 读取可执行，写入和命令被拒绝；磁盘内容不变。 | |
| P05 | 切换“规划”，要求分析修改方案并直接修改文件。 | 模型只给出计划，写入被拒绝；切回完全访问后可以修改。 | |

权限模式只约束经过适配器的工具调用，不是操作系统沙箱。

## 4. 文件 diff 与历史

| 编号 | 操作或可复制提示 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| F01 | `请使用 write 工具新建 acp-check/示例.txt，内容为三行：第一行、第二行、第三行。` | 展示新建文件 diff；可跳转到文件。 | |
| F02 | `请使用 edit 工具，把 acp-check/示例.txt 的第二行改为修改后的第二行。` | diff 只反映本次修改；定位到修改附近的行。 | |
| F03 | `请使用 write 工具覆盖 acp-check/示例.txt，内容改为两行：覆盖第一行、覆盖第二行。` | 展示覆盖前后差异，不显示为新建。 | |
| F04 | 关闭 F01–F03 所在会话，从历史重新打开。 | 回放消息、工具调用和 diff，内容与当时一致；文件不会被重新写入。 | |

## 5. 命令、用量与压缩

| 编号 | 操作 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| C01 | 新建会话后在输入框键入 `/`。 | 可见 `/status`、`/compact`、`/reload` 及已配置的 pi 命令、模板、skill；不出现 `__acp_` 内部命令。 | |
| C02 | 发送 `/status`，执行一轮任务后再发送一次。 | 显示模型、推理级别、权限模式、消息和工具数、累计 token、费用和上下文用量，数值随执行变化。 | |
| C03 | 在 B02 会话发送 `/compact 保留验证口令`，完成后询问口令。 | 显示压缩结果；之后口令仍为 `青竹482`。 | |
| C04 | 在 `~/.pi/agent/models.json` 新增一个可用模型，发送 `/reload`。 | 模型菜单出现新模型；当前模型和权限模式保持不变。 | |

## 6. 历史会话管理

只操作此次创建的测试会话。

| 编号 | 操作 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| H01 | 创建两个有消息的会话，刷新历史列表。 | 当前项目的会话出现在列表中，显示标题和更新时间。 | |
| H02 | 关闭 B02 会话，从历史重新打开并询问口令。 | 回放历史，之后可继续聊天，回答包含口令。 | |
| H03 | 删除一个专门用于删除验证的会话并刷新列表。 | 列表不再显示该会话；对应 pi 历史文件已删除；已修改的项目文件不回滚。 | |
