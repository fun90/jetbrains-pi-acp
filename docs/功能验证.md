# IDEA ↔ pi 功能验证

编写日期：2026-10-15。依据：[功能对比](功能对比.md)、[使用说明](../README.md)及当前工作区代码（含未提交修改）。

目的：在 IDEA / Air 中检查真实展示、交互和会话恢复效果。优先完成下方基础用例，再验证客户端提供入口的扩展能力。

## 1. 准备与记录

1. 使用 Node.js 22 或以上版本，先在终端确认 pi 能正常聊天。
2. 按 README 生成并合并 ACP 配置，确认启动路径指向本工作区的 `../src/index.js`。更新代码后重启 Air 的 pi Agent 连接或 IDEA，以加载代码并重新协商能力。
3. 用一个临时项目目录作为 IDEA 当前项目；下面所有测试文件都放在该目录的 `acp-check/` 内。先保存编辑器内容，避免未保存文本与磁盘内容不一致。
4. 普通文件验证使用“完全访问”；权限用例按指定模式切换。只删除专门创建的测试文件与测试会话。
5. 需要已配置的模型、skill、模板、MCP 或扩展时，先确认它们在终端 pi 中可用。模型请求可能产生实际费用。

结果统一填写：`通过 / 失败 / 阻塞 / 不适用`。界面没有入口或客户端没有协商能力时记“阻塞”，不要直接判定适配器失败；缺少测试所需模型或平台时记“不适用”。在备注中记录原因。

先让模型在完全访问模式下创建 `acp-check/权限.txt`，内容为 `原始内容`，作为下列用例的基线。每次验证都检查磁盘实际内容。

| 编号 | 操作或可复制提示 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| P01 | 切换“标准访问”，先要求读取 `acp-check/权限.txt`，再要求改为 `已批准`；在授权框选择仅允许本次。 | 内置只读工具无需授权；写入前出现授权；批准后文件才修改，后续有副作用工具仍需授权。 | |
| P02 | 标准访问下要求改为 `不应写入`，在授权框拒绝；另起一次请求，在待授权时点击停止。 | 拒绝与取消均不修改文件；取消后授权框关闭，聊天可以继续。 | |
| P03 | 标准访问下批准“本会话允许全部工具”，再要求修改文件。 | 当前会话切换完全访问，后续工具不再逐次授权；另一会话的模式不受影响。 | |
| P04 | 切换“只读”，要求读取文件，再要求写文件或用 bash 修改文件。 | 读取可执行，有副作用工具被拒绝；磁盘内容不变。bash 不因命令看起来只读就自动放行。 | |

| P06 | 仍在规划模式，明确要求写文件；随后切回完全访问，要求修改并调用 `update_plan` 更新状态。 | 规划模式拒绝写入；切回后可以执行，计划状态可更新至完成。 | |

权限验证只针对经过适配器的工具调用。权限模式不是操作系统沙箱；受信任 pi 扩展直接产生的副作用不在此边界内。

| 编号 | 操作或可复制提示 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| F01 | `请使用 write 工具新建 acp-check/示例.txt，内容为三行：第一行、第二行、第三行。` | 磁盘内容正确，工具展示新建文件 diff；文件位置可关联到项目文件。协商 Air patch 后可检查其 patch 展示。 | |
| F02 | `请使用 edit 工具，把 acp-check/示例.txt 的第二行改为修改后的第二行，保留其他行。` | diff 仅反映本次修改；定位指向修改附近的行；文件内容与 diff 一致。 | |
| F03 | `请使用 write 工具覆盖 acp-check/示例.txt，内容改为两行：覆盖第一行、覆盖第二行。` | 展示覆盖前后差异，能看到旧文本被替换，不把覆盖误显示为新建。 | |
| F04 | 用 `write` 创建 `acp-check/中文 空格.txt`、`acp-check/引号"文件.txt` 和空文件 `acp-check/空文件.txt`。 | 特殊路径可正确展示和定位；空文件确实存在；协商后的 Git patch 路径没有截断或乱码。引号路径用例在允许该文件名的平台执行。 | |
| F05 | 通过 bash 在 `acp-check/` 新增文件、修改一个现有文件、重命名并删除另一个专用测试文件；明确不要使用 `edit/write`。 | 客户端协商并请求本轮文件报告时，报告包含新增、修改、删除及重命名的旧、新路径；这类变更只要求路径报告，不要求 diff。 | |
| F06 | 创建一个 Git 忽略的测试文件和一个小二进制文件，再用 bash 修改它们。只在临时项目设置忽略规则。 | 协商且请求文件报告时，两类路径都可进入报告；二进制不要求文本 diff。 | |
| F07 | `用 bash 写入 acp-check/失败副作用.txt 后以退出码 1 结束，然后说明失败原因。` | 工具显示失败，文件仍存在；若整轮正常结束且请求了文件报告，报告包含该路径。 | |
| F08 | 关闭并从历史重新加载 F01–F03 所在会话。 | 新生成的 `edit/write` 历史回放保留对应 diff，旧、新内容与当时操作一致。历史回放不会重新执行写入。 | |

文件展示上限为 256 KiB；超过限制、二进制或无法读取时，保留工具输出即可，不要求完整 diff。旧 `write` 历史没有快照时无法补回 diff。

文件报告扫描每次最多 20000 项或 2 秒，跳过 `.git`，不跟随符号链接；扫描失败或超限应标记截断。报告保留 `declaredComplete: false`，不能当作全部修改的完整证明。取消或整轮失败时允许报告 `unavailable`。这些字段若界面不显示，可通过客户端协议日志检查，未检查时注明。

## 5. 终端展示与输入

T03–T05 执行前，更新代码并重启 Agent 连接，重新创建或恢复会话。Air ACP v1 自动启用 stdin 桥接，可通过执行中的聊天补充输入入口发送 `/stdin 文本` 和 `/eof`；普通聊天文本仍是模型提示。其他客户端需提供终端输入及 EOF 入口，并协商 `_meta.terminal_input: true`。缺少可用入口时记“阻塞”，跳过对应交互用例。

| 编号 | 操作或可复制提示 | 预期效果 | 结果 / 备注 |
| --- | --- | --- | --- |
| T01 | `请用 bash 执行 printf '开始\n'; sleep 3; printf '结束\n'。` | 有专用终端内容；客户端协商输出增量时，先出现“开始”，约 3 秒后出现“结束”，而非结束后一次性显示；退出码为 0。 | |
| T02 | `请用 bash 执行 printf '错误示例\n' >&2; exit 7。` | 终端可见 stderr，工具状态反映失败，退出码为 7；下一轮仍可执行。 | |
| T03 | `请用 bash 执行 IFS= read -r line; printf '收到：%s\n' "$line"。等待我手动输入，不要自行写入 stdin。`；Air v1 在执行中的补充输入入口发送 `/stdin 你好`（自动补换行）；其他客户端在终端入口提交 `你好` 并包含换行。 | 启用终端输入后，命令收到 `你好`，显示 `收到：你好` 并退出；输入关联当前工具，不串到其他会话。 | 原版本阻塞：用户反馈没有输入入口；模型返回“命令已执行，但执行环境的 stdin 立即返回了 EOF，未收到输入”。已添加 Air v1 聊天命令入口，待界面复验。 |
| T04 | `请用 bash 执行 cat，等待我手动输入。`；Air v1 分次发送 `/stdin 中文文本`，最后发送 `/eof`；其他客户端在终端入口分次输入中文，再关闭 stdin（EOF）。 | 分次输入不乱码；EOF 后命令退出；退出后不能继续向旧终端写入。没有 EOF 入口时记阻塞，并停止该任务。 | |
| T05 | 再运行 T03，但不输入，直接取消；随后重新执行 T01。 | 等待输入的进程被清理；新终端可运行；旧输入入口不能继续操作。 | |
| T06 | 在 Windows 环境使用已配置的 `powershell` 工具重复输出、非零退出及输入验证。 | 展示、退出码和输入与实际命令一致；非 Windows 环境记不适用。 | |

**实现边界：**适配器提供 stdin 桥接及 Air v1 聊天命令入口，不提供专用终端输入框。其他客户端未声明 `_meta.terminal_input: true` 时继续使用 pi 原有执行方式；立即 EOF 不代表桥接已启用或验证通过。桥接只对模型以 `interactive: true` 调用的 `bash/powershell` 开放 stdin；T03、T04 中如果工具参数没有 `interactive: true`，命令会立即读到 EOF，应记为模型未按要求调用，不是桥接故障。直接调用 `_terminal/input` 不自动补换行，`/stdin` 自动补一个换行；单次输入最多 64 KiB（包含换行）。这是 stdin 管道，不提供 PTY；不要用全屏终端程序或依赖 TTY 的密码提示作为通过标准。

| E07 | 有 ACP v2 客户端时，验证初始化、new/list/resume/close、配置、提示确认、并发授权状态、排队取消、执行失败及重复历史回放。 | 提示插入后返回 messageId；取消结束报告 cancelled，失败报告 error；关闭响应晚于取消完成。resume 的 null 不回放，start 回放含压缩摘要，消息和终端内容不重复追加；未声明能力不视为必需项。仅有 v1 客户端时记不适用。 | |
| E08 | 客户端声明 `elicitation.url`，扩展按 README 事件契约发起 URL 请求；接受后核实网页结果，再发送完成事件。另测拒绝、取消及客户端不支持。 | 展示网址并征求同意；接受仅表示打开网页，核实后收到 `elicitation/complete`；拒绝/取消不发送完成通知，无能力时不弹表单；跨会话及重复完成被忽略。 | |

没有现成表单扩展、MCP 或协议日志入口时，记录阻塞即可；本轮不要求为验证新增实现。

## 9. 不作为当前通过标准的能力

以下能力在功能对比中标为未实现或暂不必实现，缺少入口不判为本轮回归失败：

- 专用 Markdown 计划流与审核、原生图形登录和 provider 管理。
- 任意 MCP 服务端的完整 elicitation 桥接（含 URL 自动接入）。
- 未采用桥接契约的第三方私有子 agent 扩展，以及没有父子关系记录的旧历史自动迁移。
- 单轮独立费用、后端类型化错误的精确分类。
- 额外工作目录配置、goal 独立完成审计及费用预算管理。
- 客户端 `fs/*` 与 `terminal/*` 执行、PTY 交互，以及 ACP v2 未声明的可选能力。


## 子 agent 与后台任务验收

1. 重启 Agent 连接，协商 `subagents` 或 `nativeSubagentSessions` 以及 `asyncTasks`。
2. 要求模型使用 `spawn_agent` 执行简短任务，确认独立会话输出、完成状态及父会话可继续输入。
3. 要求模型使用 `background_shell` 启动两个长命令，确认父回合已结束但命令仍运行。
4. 用 `task_status` 或 `_session/async_task/list` 查询；定向停止一个任务，确认另一个和父会话均继续运行。
5. 尝试用其他会话的 ID 停止任务，应拒绝。关闭父会话后，确认后台命令和子 agent 全部退出。
6. 规划/只读模式拒绝启动任务；标准访问先授权再执行。未协商原生能力的客户端仍可在普通工具中查看子回答。
7. 使用 `acp:agent:spawn` 创建中层与叶子子会话，关闭并重新加载父会话，确认递归恢复关系、内容及终态。
8. 在后台命令运行时强制退出适配器，再由新适配器加载父历史，确认原任务仍可查询和定向停止，命令不重复执行。正常退出则应恢复为 stopped。
9. 分叉历史后尝试控制源任务应拒绝；子历史缺失或关系循环显示 disconnected，不自动重跑。

自动验证：`node --test test/tasks.test.js`；`PI_ACP_SMOKE=1 node --test --test-name-pattern='子 agent、后台命令|扩展桥接、递归子树' test/agent.test.js` 使用本机 pi 和本地模型替身覆盖 ACP v1/v2，不访问远端模型。IDEA 的原生卡片展示需实机验收。
